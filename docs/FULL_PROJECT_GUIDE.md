# AES Project - Guide for five weeks

## Scope and safety
Pure-Python AES-128/192/256 single-block implementation for educational evaluation, not production cryptography. The ECB/CBC/CTR/GCM modes are also instructional. Use an audited cryptography library for real secrets. **Never reuse a GCM/CTR nonce with the same key**. ECB leaks patterns; CBC padding is not authenticated and can be vulnerable if errors are exposed.

## Week 1 - Research and environment
- General cryptography, symmetric encryption, DES, AES, Rijndael and history.
- AES State, SubBytes, ShiftRows, MixColumns, AddRoundKey and rounds.
- Word, RotWord, SubWord, Rcon and AES-128/192/256 key expansion.
- Python 3.11+, VS Code, Git, repository and package layout.

## Week 2 - AES components
- `src/aes_modules.py`: original week-2 transformations.
- `src/aes_core.py`: shared encryption/decryption transforms, inverse S-box, inverse MixColumns and column-major serialization.
- `src/key_expansion.py`: expansion for 128/192/256 bits.
- `tests/test_aes_modules.py`: original component tests.

## Week 3 - Integrated implementation and attacks
- `src/aes_encrypt.py`, `src/aes_decrypt.py`: complete block cipher.
- `tests/test_integration.py`: NIST known-answer tests and round-trip checks.
- `experiments/attack_demos.py`: restricted 8-bit brute-force simulation and avalanche/diffusion illustration. Full-round AES is not broken by this demonstration.
- Cryptanalysis: brute force, differential, linear, related-key, biclique. Differential/linear/biclique attacks are advanced literature topics, not implemented as real key-recovery attacks here.
- Side channels: timing, cache, power, fault and implementation vulnerabilities are literature topics. Python benchmarks are **not** evidence of key leakage; real power/cache/fault measurements require specialized setups.

## Week 4 - Experiments
- `src/modes.py`: ECB, CBC (PKCS#7), CTR (big-endian 128-bit counter), GCM (GHASH and authenticated tag).
- `experiments/benchmark.py`: measure key schedule, encrypt, decrypt across all key lengths, CSV output.
- `experiments/plot_results.py`: three plots from CSV.
- `experiments/attack_demos.py`: ECB pattern, CBC variation, CTR tampering, GCM integrity and toy key search.
- `src/demo_ui.py`: tkinter GUI for block AES and GCM.

## Week 5 - Report and presentation
Suggested report chapters: Introduction, AES theory and key expansion, implementation and tests, attacks and countermeasures, experiments and interpretation, conclusion and references.
Figures: AES flowchart; round-trip diagram; 3 timing plots; GUI screenshots; mode/attack comparison.
Tables: AES key sizes and rounds; FIPS-197 vectors; unit tests; benchmark median and mean; attack models and countermeasures.

## Reproducibility
Do not claim timings or screenshots without actually running experiments on the target machine. `results/benchmark.csv` and PNG charts are generated by the corresponding scripts. Log CPU/OS/Python version, sample count, and explain Python overhead. Repeat measurements on each machine rather than comparing across uncontrolled hardware.

## Limitations
Not independently security-audited; Python lookup tables may have timing/cache characteristics. GCM is a nontrivial implementation; tests include published NIST vectors but are not a formal security audit. Educational use only.
